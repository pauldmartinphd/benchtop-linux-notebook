## Notes: install-time encryption

From the tik installer design notes, which are undated but match `bfd0a16`.

- tik, Aeon's installer, runs in userspace, so it fits the image's systemd-boot design where kiwi's dracut installer does not. The USB image is both the installer and the payload.
- tik deploys with systemd-repart, which copies the image to the target, encrypts the root as it writes it and grows it to fill the disk in the same pass. tik's 15-encrypt post-module then writes crypttab and the kernel command line, installs the boot loader, enrolls a recovery key (shown with a QR code) and enrolls the TPM, or a passphrase when the TPM is unsuitable.
- This replaces the first-boot path: disk-encryption-tool (re-encryption in the initrd) and sdbootutil-jeos-firstboot-enroll.
- tik seals to PCRs 4, 5, 7 and 9, the configuration behind Aeon's reboot-after-unlock problem when a kernel update changes the measured PCRs. The design added a TCBL post-module, 16-tcbl-reseal, to reseal to PCRs 0, 2 and 7 and set measure-pcr-validator.ignore=yes, so that a kernel update never stops at the recovery-key prompt. It was dropped on September 24.
