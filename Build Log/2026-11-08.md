## Hibernation

- Matthew Garrett's patch set for hibernation under lockdown (LWN, November 6) recorded in the hibernation TODO in [Build Configuration](../Build%20Configuration.md) as the preferred route if it lands: openSUSE's kernel could then hibernate with lockdown, without a TCBL kernel. It needs firmware that caps PCR 5, and its PCR 5 marker would change the PCR that TCBL's disk key is sealed to.
- Correction: the main reason for a TCBL kernel is driver support and the linux-surface patches, not hibernation; Build Configuration now says so, with a TODO for it. The upstream hibernation route would remove one item from the custom kernel, not the reason for it.

## Packages and authentication

- nano in the base pattern. benchtop-patterns `d71b180`.
- Fingerprint authentication: openSUSE's fprintd-pam installs the PAM module but does not add it to the common PAM stack (only its removal script calls `pam-config -d --fprintd`). tc-benchtop-settings now runs `pam-config -a --fprintd` from a trigger on fprintd-pam, so sudo and GNOME's administrator prompts (polkit) accept an enrolled fingerprint; without one, the password is asked at once. Not yet tested; to check on the laptop: a fingerprint at a `sudo` prompt and at an administrator prompt, how long the prompt waits for the finger before it asks for the password, and that a user without a fingerprint gets the password prompt at once. benchtop-settings `ec0ba7d`.
- Fingerprint at the login screen leaves the login keyring locked (the keyring needs the password); GNOME's normal behavior with fingerprint login, recorded in [GNOME Configuration](../UX%20and%20Desktop/GNOME%20Configuration.md), with a TODO for oo7, which Fedora 45 adopts in place of gnome-keyring and Tumbleweed packages without its PAM module.
