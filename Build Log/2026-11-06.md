## Firefox

- Firefox is installed from Flathub (`org.mozilla.firefox`) in each user's own Flatpak installation, once, by the user service `tcbl-firefox.service`, after Flathub is added; a user who removes it does not get it back. While offline it retries every 10 minutes. A Firefox the user already has, in either installation, counts as installed. The USB's tik and Create User accounts have no Flathub and get no Firefox. Not yet tested on a machine. benchtop-settings `0ed91d8`.
- Firefox is the default browser, in place of Brave, because it is what most people expect. Nothing sets it explicitly: it is the only browser installed, so GNOME uses it.
- Brave: briefly considered in place of Firefox, then dropped; the Brave enterprise policy is removed from tc-benchtop-settings. Correction: Flathub's Brave does read the host's `/etc/brave/policies` (it has `--filesystem=host-etc`, and its launcher links the host's policy files in); the earlier statement that it probably could not was wrong. benchtop-settings `d9d8d36`.
- Firefox ESR wanted instead of the rapid release; no ESR Flatpak exists, Tumbleweed has an rpm. Paused; recorded as a TODO in [Browser Configuration](../Applications/Browser%20Configuration.md).

## Default applications and Flatpak themes in one service

- `tcbl-themes.service` merged into `tcbl-default-applications.service` (script `/usr/libexec/tcbl/default-applications`, formerly `themes-for-flatpak`), and `tcbl-themes.timer` removed. At every login it installs Firefox and adw-gtk3 once (a user who removes Firefox does not get it back), installs Kvantum for every KDE runtime branch that Flathub still supports and every one the user has, and copies the Kvantum themes. The timer's job, Kvantum for runtimes that appear during a session, now waits for the next login. benchtop-settings `706a04a`.
- Checked in a test installation (Flatpak 1.14.6): installing `org.kde.KStyle.Kvantum//6.10` installs that extension alone (11.7 MB), not the KDE runtime. Flathub on November 6: supported KDE runtimes 5.15-25.08, 6.10 and 6.11; Kvantum is built for 5.15-25.08 and 6.10, not 6.11. The script was run against Flathub with installs logged: Firefox and adw-gtk3 the first time only, Kvantum skipped where installed.
- After the update, tc-benchtop-settings removes the enablement links of the old unit names (`tcbl-flathub`, `tcbl-firefox`, `tcbl-themes`, `tcbl-x86-64-v3`) if they point nowhere.
- It keeps trying: while a step that needs the network fails, the service tries again for as long as the session lasts, first after 5 minutes and then with growing waits up to an hour (`RestartSteps=4`, `RestartMaxDelaySec=1h`: about 5, 9, 17, 32 and then 60 minutes), and again at each login, since Wi-Fi is often not set up at the first login. A 30-minute cap was tried and dropped: a laptop that is suspended rather than logged out could go days without its applications. Nothing is marked done until it succeeds. benchtop-settings `7d08ebc`, `e9536b2`, `2147ae1`.
