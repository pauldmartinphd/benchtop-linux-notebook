## Hardware rules from other projects

- Copied unchanged into tc-benchtop-settings, adding hardware support without overriding any existing TCBL rule: game-devices-udev (27 files: controllers, arcade sticks, flight and racing hardware, VR), Universal Blue (Framework Laptop 16, HORIPAD STEAM, Wooting, Apple SuperDrive), CachyOS (HDA power saving off on AC power with audio-pm-ctl, NVIDIA runtime power management, /dev/cpu_dma_latency for the audio group) and iw-setregdomain (wireless regulatory domain from the timezone).
- Not copied: three Universal Blue rules that make device nodes writable by everyone (ZSA, Arduino, Neutron); six more that are redundant, unsafe or ineffective (10-switch, 50-usb-realtek-net, 70-u2f, 70-titan-key, 92-viia, 99-thinkpad-thresholds); CachyOS's zram, SATA, hdparm, hpet and I/O-scheduler rules. CachyOS's thp.conf, thp-shrinker.conf, coredump.conf and dns.conf were already matched.
- Finding: the image had no wireless regulatory database, so every machine was held to the world domain. tc-benchtop-settings now requires wireless-regdb.
- Upstream tracking: upstream.list records each source's commit; scripts/check-upstream reports changes, and --apply copies them for review. A pre-push hook runs the check and reminds without blocking the push.
- Build checks: the package built locally, all copied rule files pass udevadm verify, and two dependency names were corrected before the push (tzdata is timezone on Tumbleweed; logger comes from util-linux-systemd).

## Install test (evening)

- Installed from the USB onto an 8 TB WD SN850X in an HP laptop. The disk step showed only "Deploying OS Image" throughout. After the root was encrypted, the copy into the new Btrfs file system did no reading, writing or computing for several minutes while a kernel worker waited on a device, then copied at about 30 MB/s.
