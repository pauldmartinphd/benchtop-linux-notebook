## YaST arrived with an update

- The update of October 30 (21:35) installed YaST's core, libraries and about a dozen modules on the laptop. The chain: the admin set requires `samba`; openSUSE's `yast2-samba-server` declares `Supplements: samba` (bnc#386473), so the solver added it, and it requires `yast2`; once `yast2` was there, other modules joined through their own supplements, such as `(snapper and yast2)`. The installer was not affected, since it installs the package sets with `--no-recommends`; the next update, which follows optional dependencies, was.
- Fix: the base pattern conflicts with `yast2` (and, moved there from tc-benchtop-settings, with `flatpak-remote-flathub`): exclusions belong to the package set; TCBL is administered with Cockpit. Supplements are optional, so the solver leaves YaST out instead of failing. To report upstream: `yast2-samba-server` could supplement `(samba and yast2)`, as `yast2-snapper` does with snapper. Systems that already have YaST must remove it (or roll back) before the update with the conflict, which an unattended update cannot resolve on its own.
- Automatic updates were confirmed as configured: `transactional-update.timer` daily, `REBOOT_METHOD=notify`, and `transactional-update-notifier` for the restart notification.
